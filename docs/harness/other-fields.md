# Other fields

The fourth section says how other fields solve similar problems with the same abstraction and
formulation (the user's rule, 2026-11-10).

## Which fields belong

- A field belongs when the problem of the field fits the
  [formulation](problem.md#formulation) of the survey. Test the fit object by object.
- A field with a similar keyword and a different problem does not belong.
- Prefer fields with measurements and mature mechanisms.

## Describing a mechanism

Give four facts for each mechanism.

1. The role of the mechanism in the formulation.
2. The counterpart for a robot system.
3. The state of the counterpart in robotics (exists, exists in part, not found). Search before
   writing "not found" ([challenges](challenges.md#gaps)).
4. The part without transfer. Every transfer loses something, and the survey names the loss.

## The transfer argument

- State a transfer from another field to robots as an argument of the survey.
- Build the argument in steps. Map each object of the other field to an object of the robot
  problem, then name the assumption of the other field without a robot equivalent.
- Read classical sources in the original, or mark the citation as supporting the core idea
  only ([literature](literature.md#status)).

## The map

- End the section with one table. Each row is one mechanism, with the origin, the robot
  counterpart and the state in robotics.
- Follow the table with one paragraph on the pattern of the table (which kinds of mechanisms
  have counterparts and which kinds do not).
