# Problem

The first section of a survey states the scientific problem. The section says what the survey
discusses and tries to understand, before any method appears (the user's rule, 2026-11-10).

## Motivation

- Start from a need. Name the actor, the missing thing, and the consequence of the lack.
  Pattern, "X needs Y, because without Y, X cannot Z. Field A provides Y. Field B does not. The
  survey studies how to provide Y in B."
- Do not motivate a survey by a capability alone, such as "models can now do X, so someone has
  to study X" (the user's rule, 2026-11-10, after the user rejected a first draft with "The
  motivation is wrong").
- Support the need with one concrete piece of evidence, verified in the source.
- Keep the motivation to two or three short paragraphs.

## The question

- State one question, in one to three sentences, and set the question apart in a
  `blog-callout`.
- The question names the object of study, the setting and the unknown.
- Every later section answers a part of the question. A section without a link to the question
  does not belong in the survey.

## Formulation

- Give one formulation for the whole survey. Name the objects, give each object a symbol and a
  one-line definition, and give one example of each object in a robot system. A table works
  well.
- State the central relation of the problem on a display line, then say in words what the
  relation does and does not establish.
- Decompose the problem into parts (links, stages or conditions). Say for each part what
  failure looks like. The parts place every paper of the survey.
- Mark a formulation of the survey's own making as such. Check a standard formulation against
  the standard source.
- Use notation only where notation carries the argument.

## Sub-questions

- List the sub-questions in a table in the working notes, each tied to one part of the
  formulation.
- State a hypothesis of the user as a hypothesis. Report the evidence on both sides
  ([challenges](challenges.md#conflicting-evidence)).

## Running example

- Pick one system as the running example. Choose a system close to the centre of the question.
- Describe the example with verified facts and with the limits stated by the authors of the
  example.
- Say which parts of the formulation the example covers and which parts the example leaves
  open.

## Scope

- Write a table of topics in scope and out of scope in the working notes, and confirm the
  table with the user.
- Link to neighbouring surveys on the blog. Do not repeat the content of a neighbouring survey.
