# Literature

The rules for reading, verifying and searching sources. Each survey has a source index in the
working notes ([workflow](workflow.md#working-notes)).

## Before a source enters the survey

1. Find the source in the source index. Add a missing source first.
2. Open the abstract page. Check the identifier, the title, the authors and the venue.
3. Read the abstract in full before writing any sentence about the paper (the user's rule).
   After shortening a sentence, check the sentence against the abstract again.
4. For a number, find the number in the paper and note the table or section.
5. Write the read date in the index.

A draft, a summary by someone else or a model's memory is not a reading. Verify every claim
taken from a draft of the user as well.

## The source index

One row for each source, with the identifier and venue, the authors, the status, the open
checks and the read date. A second table lists every search.

### Status

| Status | Meaning | May enter the survey |
| --- | --- | --- |
| A | Abstract page read, and the full text for every quoted number | Yes |
| B | Bibliographic record and core idea confirmed, full text not read | For the core idea only |
| K | Listed from memory or from a draft, not opened | No |
| X | A field is in conflict or missing | No |

## Numbers

- Every number has a source, a status and the object of the measurement.
- Quote the words of the paper for a headline result.
- Give the version when versions of a paper differ.
- Give a venue only when the arXiv page or the publisher states the venue.
- Do not turn an absolute difference into a relative difference, or the reverse, without the
  two raw values.
- Say which rows of a table a number covers.
- Label a number from a preprint, a workshop paper, a project page or a second-hand source.
- Drop a number without a confirmed source.
- A number measured in one field says nothing direct about another field. State the transfer
  as an argument.

## Quality

The user's rule. Build the argument on rigorous sources and use other sources as single
supporting facts.

- Rigor means peer review, a controlled comparison, a held-out evaluation, stated limitations
  and released code.
- Sort the candidate sources of a section by rigor before writing, and read the top sources
  in full.
- Use new preprints, label new preprints, and do not let one preprint carry the claim of a
  section alone.
- A post without peer review can supply an argument and cannot supply a fact.

## Searching

1. Read the searches table of the index. Do not repeat a recorded search.
2. Search for the abstraction as well as the keywords. A paper solving the problem under
   another name counts.
3. Record the query, the date, the place and the result, including "nothing".
4. Open each candidate before reporting the candidate.
5. A [gap](challenges.md#gaps) needs a search for counterexamples.

## Claims about absent features

- "The paper does not do X" needs a reading of the method section, not only of the abstract.
- Separate statements of the paper from readings of the survey.
- Write "not found" where a source is silent.

## Disagreement

When a source disagrees with the notes or the survey, fix the index, the notes and the survey
in the same change. Tell the user when the fix changes a challenge, a gap or the map.
